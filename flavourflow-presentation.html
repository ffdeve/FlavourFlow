The Problem

"What's for dinner?" — every single day

  • Deciding what to cook daily is repetitive and stressful.
  • Existing apps (Tasty, Yummly, HelloFresh) are built for Western ingredients and kitchens.
  • No support for local cuisine, halal rules, or Urdu.
  • No way to cook from what you already have at home.
  • No real-time, hands-free cooking guidance.
🎯

Our users

Busy parents, students living away from home, novice cooks, and dietary planners — people who need quick, culturally-relevant, allergy-aware meal ideas.

How ChefBoo Answers You

AI Logic

Recommendation Algorithm

Final Score =
  Content match (spice / diet)
+ Behaviour (time-decayed actions)
+ Trend (community activity)
+ Context (time of day / weekend)
− Penalty (quick exits, abandons)
  • Cooking a recipe counts far more than viewing it.
  • Older actions decay over time.
  • Recipes sort into rows: For YouTrendingCook It AgainJump Back In
  • New users get smart cold-start picks.
  • Runs continuously as a background job → the app keeps learning.

Security & Reliability

🔒

Row Level Security

Every table locked so users touch only their own data.

🔑

Secret isolation

AI & service keys live server-side only — never in the app.

🌐

TLS everywhere

All traffic encrypted in transit; passwords hashed by Auth.

🛡️

Abuse guard

Per-user AI rate limits + safety filter on ChefBoo.

📴

Offline resilience

Network detection, retry screens, graceful errors.

🔔

Reliable timers

Cooking alerts fire even when the screen is off.

Project Structure

src/ ├─ app/ screens (Expo Router) │ ├─ (auth)/ login · signup · onboarding │ ├─ (tabs)/ home · community · create │ │ · alerts · profile │ ├─ recipe-detail · cooking-mode │ ├─ ai-chat · ai-recipe-detail │ └─ create-recipe · search · settings ├─ components/ui/ reusable UI ├─ services/ API layer (Supabase) ├─ store/ Zustand state ├─ hooks/ · utils/ · types/ supabase/ ├─ functions/ ai-chat · recommendations │ · send-push (Deno) └─ migrations/ versioned SQL schema

Clean separation of concerns

  • Screens render UI & call services.
  • Services hold all database/API logic.
  • Store keeps global session & timers.
  • Edge functions run trusted server-side logic (AI, ranking, push).
  • Migrations version every schema change.
