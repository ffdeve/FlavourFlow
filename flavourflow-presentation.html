The Problem

Dinner shouldn't be a daily negotiation

  • Deciding what to cook is a decision most people make daily, with too little time and no help.
  • Tasty, Yummly, and HelloFresh are built around Western pantries and Western ingredients.
  • None of them speak Urdu, respect halal constraints, or know what a karahi is.
  • None of them start from what's already in your kitchen.
  • None of them stay with you once you're actually cooking.

Who we built this for

Busy parents, students cooking for themselves for the first time, and anyone who wants a recipe that fits their taste, diet, and pantry — not a generic list of "50 Pakistani recipes."

The Solution

One companion, from "what's for dinner" to dinner's done

AI Logic

Recommendation algorithm

Final Score =
  Content match (spice / diet)
+ Behaviour (time-decayed actions)
+ Trend (community activity)
+ Context (time of day / weekend)
− Penalty (quick exits, abandons)
  • Cooking a recipe counts far more than viewing it.
  • Older actions decay over time.
  • Recipes sort into rows: For YouTrendingCook It AgainJump Back In
  • New users get smart cold-start picks.
  • Recomputed automatically by a scheduled job every 15 minutes — no manual refresh, ever.

AI · Cooking Mode

The app keeps working while your hands are busy

  Timers that survive real life

  • Remaining time is recomputed from the wall clock on every tick — never a counter that just stops when the app backgrounds, locks, or gets killed.
  • Run several timers at once, each with its own scheduled local notification, sound, and haptic.
  • A floating tray keeps every active timer one tap away without leaving the recipe.

  ChefBoo becomes a sous-chef

  • Mid-recipe, ChefBoo switches to a constrained mode: substitutions, conversions, and troubleshooting only — no recipe pitches while your hands are busy.
  • Answers are one to three sentences, readable at a glance.
  • Say "set a 5 minute timer" and it starts one — parsed locally first, no network round trip for the common case.

Security & reliability

Row Level Security

Every table locked so users touch only their own data.

Secret isolation

AI & service keys live server-side only — never in the app.

TLS everywhere

All traffic encrypted in transit; passwords hashed by Auth.

Abuse guard

Per-user AI rate limits + a safety filter in front of ChefBoo.

Offline resilience

Network detection, retry screens, graceful errors.

Structured AI output

Gemini's recipe generator must return valid JSON — never loose prose — so nothing malformed reaches the UI.

Clean separation of concerns

  • Screens render UI & call services.
  • Services hold all database/API logic.
  • Store keeps global session & timers.
  • Edge functions run trusted server-side logic (AI, ranking, push).
  • Migrations version every schema change.

Engineering

Challenges & key decisions

ChallengeOur solution
Keeping every user's data privateRow Level Security on every table + owner-only policies
AI cost & potential abuseDatabase-first search + per-user rate limiting (30/hr, 100/day)
Timers must fire with the screen offWall-clock-accurate remaining time + pre-scheduled local notifications
Secrets must never leak to the clientAll keys in server-side env / edge functions only
Personalization that keeps improvingBehaviour-weighted learning loop with time decay, recomputed on a schedule
A scheduled job can fail silentlyThe recommendation cron was missing its auth header for a stretch of production time — caught it by auditing the job, fixed it, learning resumed within minutes
